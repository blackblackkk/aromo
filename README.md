# Ароматно и точка •

Сайт интернет-магазина оригинальной парфюмерии: каталог с фильтрами, распив от 2 до 50 мл, корзина, избранное, оформление заказа.

Статический сайт без сборки: HTML, CSS и JavaScript. Открывается двойным щелчком по `index.html` и размещается на любом хостинге, включая GitHub Pages (Settings → Pages → ветка `main`, папка `/`).

## Что где лежит

| Файл | Что в нём |
| --- | --- |
| `index.html` | Каркас: шапка, подвал, корзина, меню |
| `assets/css/style.css` | Оформление; палитра и шрифты — в начале файла |
| `assets/js/config.js` | Контакты, способы доставки, адрес для приёма заказов |
| `assets/js/data.js` | Каталог, объёмы распива, семейства ароматов |
| `assets/js/app.js` | Страницы, фильтры, поиск, корзина, оформление |
| `assets/img/` | Логотип и значок сайта |

## Перед запуском

1. **Каталог.** В `data.js` лежит демо-наполнение: 45 ароматов с условными ценами. Замените его своими позициями и ценами.
2. **Цена распива.** Считается в `app.js`, функция `decantPrice`: цена миллилитра во флаконе × 1,25 + 60 ₽ за атомайзер. Подставьте свою формулу или пропишите цены вручную.
3. **Контакты.** Заполните `config.js` — телефон, Telegram, WhatsApp, почту, юридическую строку.
4. **Приём заказов.** Укажите в `config.js` поле `orderEndpoint` — адрес, который принимает POST с JSON заказа (сервер, CRM, бот). Пока поле пустое, сайт показывает покупателю готовый текст заказа, чтобы отправить его менеджеру.
5. **Доставка и оплата.** Проверьте список способов доставки в `config.js` и тексты страницы «Доставка и оплата» в `app.js`.
6. **Документы.** Добавьте политику обработки персональных данных и оферту и поставьте на них ссылки в подвале и в форме заказа.

## Адреса страниц

`#catalog`, `#brands`, `#decant`, `#delivery`, `#about`, `#favorites`, `#checkout`, `#product-<id>`.

Корзина и избранное хранятся в браузере покупателя (`localStorage`).

Каталог на 30 000 позиций в одном файле работать не будет — для полного ассортимента нужна выгрузка из учётной системы или CMS с постраничной загрузкой.

## Перенос на домен

Все пути на сайте относительные, поэтому он работает и в корне домена, и в подпапке. Уже готово: `404.html`, `robots.txt`, `site.webmanifest`, значки, картинка для превью ссылок (`assets/img/og.jpg`), `.nojekyll`.

Когда домен известен, нужно дописать четыре вещи (везде — адрес с `https://`):

1. `index.html`: добавить `<link rel="canonical" href="https://ДОМЕН/">` и `<meta property="og:url" content="https://ДОМЕН/">`, а в `og:image` указать полный адрес `https://ДОМЕН/assets/img/og.jpg` — мессенджеры не показывают превью по относительной ссылке.
2. `robots.txt`: добавить строку `Sitemap: https://ДОМЕН/sitemap.xml`.
3. Создать `sitemap.xml` с адресом главной.
4. Для GitHub Pages — файл `CNAME` с доменом в одну строку.

### Если хостинг — GitHub Pages

1. В репозитории: Settings → Pages → Source: ветка `main`, папка `/`.
2. У регистратора домена, в DNS:
   - четыре A-записи для корня домена: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - CNAME-запись `www` → `blackblackkk.github.io`.
3. Settings → Pages → Custom domain: вписать домен, дождаться проверки DNS и включить Enforce HTTPS.

### Если хостинг свой

Загрузите содержимое репозитория в корневую папку сайта, включите HTTPS и укажите `404.html` как страницу ошибки.
